## Rate limit

Each API key can make **120 requests per minute** across every job route. The window starts with the first request and resets one minute later. Request 121 inside the window returns `429 rate_limited`.

The limit is per key, not per account. Uploads and downloads through signed URLs do not count, and neither does `GET /v1/formats`.

Every response to a job route carries the window's state:

| Header                  | Value                                          |
| ----------------------- | ---------------------------------------------- |
| `X-RateLimit-Limit`     | `120`                                          |
| `X-RateLimit-Remaining` | Requests left in this window                   |
| `X-RateLimit-Reset`     | Seconds until the window resets                |
| `Retry-After`           | On `429` only: seconds to wait before retrying |

A `POST /v1/convert` that waits for its result counts as one request, however long it waits.

## Sizes and counts

| Limit                                               | Value                                  |
| --------------------------------------------------- | -------------------------------------- |
| Input file size, jobs routes and `source_url`       | 1 byte to 2,000,000,000 bytes (2 GB)   |
| Input file size, body of `POST /v1/convert`         | 1 byte to 25,000,000 bytes (25 MB)     |
| Wait for a `POST /v1/convert` result                | 120 seconds by default, at most 300    |
| Jobs from the last 24 hours, per account            | 100 by default; we raise it on request |
| Declared input bytes across those jobs, per account | 50 GB                                  |
| Outputs per job                                     | 256 files, 4 GB in total               |
| Conversion time per attempt                         | 10 minutes                             |
| Attempts per job                                    | 3                                      |

Every job holds one of those slots until it expires, so the default allows about 100 conversions per rolling 24 hours. [Contact us](https://convt.app/contact) to raise it. The storage limits count every job created in the last 24 hours, including cancelled and failed ones, until the job's files are deleted at expiry.

## Lifetimes

| Item                              | Valid for                                                          |
| --------------------------------- | ------------------------------------------------------------------ |
| `upload_url`                      | 15 minutes after the job is created                                |
| Output download URLs              | `expires_in` seconds, at most 5 minutes; request new ones any time |
| A job, its upload and its outputs | 24 hours after creation                                            |

## Spend cap

Each job reserves 1 cent when it is created and is billed only if it succeeds. Once billed plus reserved spend reaches your cap for the billing period, creating a job returns `403 limit_reached`. Change the cap on the [dashboard](https://convt.app/dashboard/api).
