---
title: JavaScript SDK
description: Convert files from Node, Bun, Deno or a server route with @convt/sdk.
---

`@convt/sdk` wraps the HTTP API: one call reserves the job, uploads, starts, polls and returns the outputs. It has no dependencies.

```bash
npm install @convt/sdk
```

```ts
import { Convt } from "@convt/sdk";

const convt = new Convt(); // reads CONVT_API_KEY, or pass { apiKey }
const result = await convt.convert("report.docx", { to: "pdf" });
await result.save("report.pdf");
```

`convert()` takes a file path (Node, Bun and Deno), a `Blob` or `File`, or a `Uint8Array`, up to 2 GB. It reads the input format from the file name's extension. If anything fails or you abort it, it cancels the job so the reservation is released.

To convert a file that is already online, pass its URL. convt downloads it, so nothing goes through your machine:

```ts
const result = await convt.convertUrl(
  "https://my-bucket.s3.amazonaws.com/clip.mov?X-Amz-Signature=...",
  {
    to: "mp4",
  },
);
```

## Options

| Option       | Type            | Description                                                                    |
| ------------ | --------------- | ------------------------------------------------------------------------------ |
| `to`         | `Format`        | Target format id. Required.                                                    |
| `from`       | `Format`        | Input format id. Needed when the file name or URL has no recognized extension. |
| `options`    | `JobOptions`    | Conversion settings such as `quality`, `max_size`, `pages` or `trim_start`.    |
| `webhookUrl` | `string`        | Gets a signed POST when the job finishes. See [Webhooks](/guides/webhooks).    |
| `signal`     | `AbortSignal`   | Cancels the conversion and the job.                                            |
| `onProgress` | `(job) => void` | Called with the job after each poll.                                           |
| `timeoutMs`  | `number`        | Gives up and cancels after this long. Defaults to 660,000 (11 minutes).        |

The client takes `{ apiKey, baseUrl, maxRetries }`. `baseUrl` defaults to `{{api}}`; `maxRetries` (default 2) bounds retries of rate limits and gateway errors.

## Results

`convert()` returns a `Conversion` with `job`, `outputs`, and helpers to read them:

- `blob(index = 0)` downloads one output as a `Blob`.
- `save(path)` writes the only output to disk. Node only.
- `saveAll(directory)` writes every output into a folder under the names the API returns, such as `input.png` and `input-2.png`. Node only.

## Your own idempotency key

Pass `idempotencyKey` (an order id, say) and a second run after a crash returns the same job instead of converting again. With your own key the SDK:

- sends the file's SHA-256 as `input_sha256`, so a retry that would upload different bytes under that key fails with `idempotency_key_reused` instead of converting them;
- never cancels the job for you, because another call with the same key may be waiting on it. A deadline or abort throws `stopped_waiting` with `jobId`; call `convt.cancel(jobId)` if you want the job stopped.

Without a key, each call uses its own and cancels its job when it fails or you abort, so the reservation is released.

## Retries and errors

Every job is created with a fresh [`Idempotency-Key`](/guides/idempotency), so the SDK can retry a create whose response was lost without reserving twice. It retries `429`, `502`, `503` and `504` with backoff, honoring `Retry-After`, on calls that are safe to repeat.

Errors are `ConvtError` instances with the API's `code`, the HTTP `status`, the `requestId` from `X-Request-Id` and, once a job exists, its `jobId` and `idempotencyKey`. A conversion that succeeded but whose output links failed throws `download_failed` with `jobId`: it was billed, so call `convt.download(jobId)` rather than converting again.

## Webhooks

```ts
import { verifyWebhook } from "@convt/sdk";

const { secret } = await convt.webhookSecret(); // fetch once, store it
const event = await verifyWebhook({ body: rawBody, signature: headers["convt-signature"], secret });
```

`verifyWebhook` checks the HMAC and the timestamp, then returns the typed event. See [Webhooks](/guides/webhooks).

## Lower-level calls

`create`, `start`, `status`, `cancel`, `download` and `webhookSecret` map one to one onto the [API routes](/api). `create(input, { idempotencyKey })` takes your own key.

## Browser apps

Never put a `cvt_live_` key in browser code. Run the SDK in your server route and send the browser the result. See [Browser apps](/guides/browser-apps) and the [server upload route](/examples/server-upload-route) example.
