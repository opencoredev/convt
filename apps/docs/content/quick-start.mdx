Create an API key on the [dashboard](https://convt.app/dashboard/api) and export it:

```bash
export CONVT_API_KEY=cvt_live_...
```

Then convert `photo.png` to WebP. `POST /v1/convert` takes the file and answers with the converted file, in one request. Each successful conversion costs $0.01; failed ones are free.

<Tabs syncKey="client" param="client">
<Tab title="cURL">

```bash
curl -fsS {{api}}/v1/convert \
  -H "Authorization: Bearer $CONVT_API_KEY" \
  -F file=@photo.png -F to=webp -o photo.webp
```

`-f` makes curl exit non-zero on an error, so a JSON error never lands in `photo.webp`. Drop it while you experiment to see the error body.

Add `-H "Idempotency-Key: $(uuidgen)"` once you script it, so a retry can't run the conversion twice. See [Idempotent requests](/guides/idempotency).

</Tab>
<Tab title="JavaScript SDK">

```bash
npm install @convt/sdk
```

```ts convert.ts
import { Convt } from "@convt/sdk";

const convt = new Convt(); // reads CONVT_API_KEY
const out = await convt.convert("photo.png", { to: "webp" });
await out.save("photo.webp");
```

The SDK uploads straight to storage, so it also takes files up to 2 GB, retries safely with an `Idempotency-Key`, and cancels the job if you abort. See [JavaScript SDK](/guides/javascript-sdk).

</Tab>
<Tab title="Python">

Uses [requests](https://requests.readthedocs.io): `pip install requests`.

```python convert.py
import os
import requests

with open("photo.png", "rb") as f:
    r = requests.post(
        "{{api}}/v1/convert",
        headers={"Authorization": f"Bearer {os.environ['CONVT_API_KEY']}"},
        files={"file": f},
        data={"to": "webp"},
        timeout=180,
    )
# 200 with a non-JSON body is the file; anything else is JSON describing the job.
if r.status_code != 200 or r.headers["content-type"].startswith("application/json"):
    raise SystemExit(f"{r.status_code} {r.text}")
with open("photo.webp", "wb") as out:
    out.write(r.content)
```

</Tab>
<Tab title="Go">

Only the standard library. Save it as `main.go` and run `go run main.go`.

```go main.go
package main

import (
	"bytes"
	"io"
	"log"
	"mime/multipart"
	"net/http"
	"os"
	"strings"
)

func main() {
	var body bytes.Buffer
	form := multipart.NewWriter(&body)
	form.WriteField("to", "webp")
	part, _ := form.CreateFormFile("file", "photo.png")
	in, err := os.Open("photo.png")
	if err != nil {
		log.Fatal(err)
	}
	io.Copy(part, in)
	form.Close()

	req, _ := http.NewRequest("POST", "{{api}}/v1/convert", &body)
	req.Header.Set("Authorization", "Bearer "+os.Getenv("CONVT_API_KEY"))
	req.Header.Set("Content-Type", form.FormDataContentType())
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		log.Fatal(err)
	}
	defer res.Body.Close()
	// 200 with a non-JSON body is the file; anything else is JSON describing the job.
	if res.StatusCode != http.StatusOK || strings.HasPrefix(res.Header.Get("Content-Type"), "application/json") {
		msg, _ := io.ReadAll(res.Body)
		log.Fatalf("%s: %s", res.Status, msg)
	}
	out, _ := os.Create("photo.webp")
	io.Copy(out, res.Body)
}
```

<Tab title="Node">

Node 20 or newer, no packages. Save it as `convert.mjs` and run `node convert.mjs`.

```js convert.mjs
import { readFile, writeFile } from "node:fs/promises";

const form = new FormData();
form.append("file", new Blob([await readFile("photo.png")]), "photo.png");
form.append("to", "webp");

const res = await fetch("{{api}}/v1/convert", {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.CONVT_API_KEY}` },
  body: form,
});
// 200 with a non-JSON body is the file; anything else is JSON describing the job.
if (res.status !== 200 || res.headers.get("content-type")?.startsWith("application/json"))
  throw new Error(`${res.status} ${await res.text()}`);
await writeFile("photo.webp", Buffer.from(await res.arrayBuffer()));
```

<Tab title="CLI">

The convt CLI converts on your own machine. It needs no API key and uploads nothing, so it is the right tool for scripts that run where convt is installed. Get it from the [download page](https://convt.app/download).

```bash
convt photo.png --to webp
convt ./photos -r --to webp -j 4
```

Run `convt targets photo.png` to see every format a file can become. AI coding agents can print a `SKILL.md` with `convt --skill`.

## What just happened

1. convt reserved one conversion against your spend cap, stored the upload and queued the job, the same pipeline every API job uses.
2. A worker converted the file in a sandbox with no network access.
3. The response was the converted file, with `Content-Disposition: attachment; filename="photo.webp"` and a `Convt-Job-Id` header naming the job.

The job, its upload and its output are deleted 24 hours after it was created.

## Options, formats and other inputs

- Settings go in an `options` field as JSON: `-F 'options={"quality":80,"max_size":2048}'`. [Options](/api) lists them all.
- `to` and `from` take a format id or an extension, so `to=jpg` works. convt reads the input format from the file name; pass `from` when it has none. [Formats](/reference/formats) lists every pair.
- Send the file as the raw body instead of a form: `curl --data-binary @photo.png "{{api}}/v1/convert?to=webp&from=png" ...`.
- Convert a file already in S3, R2 or on a CDN without downloading it first: send `{"source_url": "https://...", "to": "webp"}` as JSON. See [Remote files](/guides/remote-files).
- A PDF with several pages produces several files, so the answer is JSON with a signed URL for each. Send `Accept: application/json` to always get JSON, or `options={"pages":"1"}` for one page.

## When the answer is not a file

convt waits up to `wait` seconds for the result (default 120, at most 300). What happens next depends on what you asked for:

| Status | Meaning                                                                                                                                            |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `200`  | The converted file, or JSON when there are several outputs or you sent `Accept: application/json`.                                                 |
| `202`  | You asked for JSON and the job is still running. It keeps going; poll the `Location` it returns. `wait=0` answers at once.                         |
| `409`  | `still_running`: you asked for the file and sent an `Idempotency-Key`. The job keeps going; send the same request with the same key to collect it. |
| `504`  | `timeout`: you asked for the file without a key. The job was cancelled and you were not charged. Raise `wait`, send a key, or use the jobs routes. |
| `413`  | Over 25 MB. Use [the jobs routes](/guides/uploading), which take 2 GB, or `source_url`.                                                            |
| `422`  | The conversion failed. You are not charged.                                                                                                        |
| `4xx`  | A bad request, key or spend cap. The JSON `error.code` says which; see [Errors](/reference/errors).                                                |

Without an `Idempotency-Key`, hanging up before the answer cancels the job. That is best effort: if the conversion already succeeded, it is billed. To retry safely instead, send an [`Idempotency-Key`](/guides/idempotency); a retry with the same key picks up the same job rather than starting another.
