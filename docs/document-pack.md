# Document pack

Images, video, audio, PDF and SVG ship with convt and work offline immediately. Documents, presentations and spreadsheets use an optional LibreOffice pack. Selecting one of these files offers an Install document support button. Selecting a file, opening the dialog, inspecting targets and checking pack status never download anything. The app starts the download only after the user clicks Install. The CLI equivalent is `convt pack install documents`.

The pack contains LibreOffice Writer, Calc and Impress, their filters, configuration, fonts and native dependency closure. It runs headlessly with a private profile per conversion. Linux uses a relocatable tree and launcher rather than installing distro packages into the system. A custom headless build might omit help, language packs, GUI backends, Java and unused filters, but it needs its own conversion-matrix coverage. The current local proof uses LibreOffice 7.3.7 from Ubuntu 22.04 with its FHS bootstrap paths rewritten to its private tree, dynamically loaded NSS modules included, and a small source-included shim that points liblangtag at bundled language data. It supports the five tested Linux distributions from Ubuntu 22.04 and Debian 12 onward. Its glibc 2.35 baseline is separate from the main bundle’s glibc 2.28 baseline. It is not a release pack assembled from pinned source packages.

macOS should use a signed and notarized LibreOffice app tree in the pack. Windows should use a portable LibreOffice tree with a launcher that isolates its DLL search path. Repackage each platform as a tar.gz with a top-level `soffice` launcher on Unix or `soffice.exe` on Windows. The installer accepts regular files and directories only. Materialize internal symlinks when making packs; no archive may contain links, device nodes or paths outside its root. macOS signature preservation after materializing links requires a Mac to verify. Windows verification packaging extracts the pinned LibreOffice 25.8.7 MSI with lessmsi, retains its tree and notices, and adds a native `soffice.exe` launcher. The launcher isolates PATH to the private program directory and System32, waits for Office, and contains its descendants in a kill-on-close Windows job so cancellation stops the whole conversion. Windows verification still builds that archive and pins its digest, but the per-user MSI does not carry `documents.tar.gz`. Installation remains an explicit user action, matching Mac and Linux: a hosted URL once one exists, or `convt pack install documents --source file:///absolute/path/documents.tar.gz --sha256 <compiled-digest>` for a local proof.

## Location and discovery

The proof pack generates a private temporary fontconfig file with absolute font paths. This supports older fontconfig versions without changing the conversion working directory. The launcher deletes the file when its child process exits.

Packs live under the per-user convt data directory, with no root permissions:

- Linux: `$XDG_DATA_HOME/convt/packs/documents`, normally `~/.local/share/convt/packs/documents`.
- macOS: `~/Library/Application Support/convt/packs/documents`.
- Windows: the platform data directory under `%APPDATA%\convt\packs\documents`.

`CONVT_DATA_DIR` overrides the convt data directory for tests and managed installs. Each verified archive installs into a directory named by its SHA-256. Discovery requires that digest to match the pin compiled into the running build. The `current` pointer and `verified.sha256` receipt must both match that pin; an arbitrary digest and matching receipt are insufficient. The launcher must be a regular executable file inside the pack tree. Discovery rejects symlinks, special files, and paths owned by another user or writable by the group or everyone. These checks cover the pack root, every directory and file in the selected tree, the pointer and receipt. Paths leading to the pack root must also be directories free of symlinks, owned by the current user or root, and not writable by the group or everyone. A sticky ancestor such as root-owned `/tmp` is the exception: its sticky bit prevents other users from renaming or removing the next component, whose ownership and permissions are checked in turn. This permits a private user-owned temporary directory under `/tmp`; it does not permit a shared writable pack root. The pack root and everything inside it must still be owned by the current user and have no group/world write permissions. An insecure `CONVT_DATA_DIR` or other ancestor is rejected during discovery, installation and removal. Windows checks each object through a handle without following reparse points. It permits the current user, SYSTEM and Administrators as owners and mutation principals; TrustedInstaller may own an ancestor. It rejects null DACLs, unsupported ACEs, other-user mutation grants and all reparse points. Ancestors may allow sibling creation when the next component already exists, but not child deletion, ACL changes or replacement. A missing component requires a private existing parent. Pack paths also reject unsafe inheritable mutation grants. Unix checks remain unchanged.

Extraction happens in a temporary sibling directory. Every install verifies the archive against the expected digest and extracts a fresh tree, including when a directory with a matching receipt already exists. A complete cached `.partial` archive can support an offline retry after verification; a receipt alone cannot. The installer moves an existing tree aside only after the replacement passes verification and extraction, then publishes the replacement and pointer. Successful installation removes the cached archive.

LibreOffice discovery checks `CONVT_SOFFICE`, then an executable beside convt, then the installed pack, then PATH. A system LibreOffice remains usable. `convt pack status documents` reports the per-user pack and explains why an unavailable or invalid pack was rejected, separately from whether system Office is available. The pack name is optional for status and defaults to `documents`; other names are rejected. The engines never install a pack themselves. After successful installation the app must rebuild `default_registry()` so all clients use the same available targets.

## Integrity, transfers and lifecycle

Release builds embed the URL, SHA-256 and version through `CONVT_DOCUMENT_PACK_URL`, `CONVT_DOCUMENT_PACK_SHA256` and `CONVT_DOCUMENT_PACK_VERSION`. CI must provide one audited archive digest for each platform and version. The only source placeholder is `documents_source()` in `crates/convt-engines/src/packs.rs`. Its empty hash makes an unconfigured build fail before any request. No hosting exists yet. A future signed manifest can replace compiled pins, but it must be verified with a separate embedded Ed25519 public key before its URLs or digests are trusted.

The downloader requires HTTPS on the initial request and every redirect, uses Rust TLS support, saves a resumable `.partial` file, and uses HTTP Range on retry. Explicit `file://` sources are also supported. Loopback HTTP is enabled only in unit-test builds and does not follow redirects. If a server ignores Range it starts again. It validates the resumed offset and verifies the entire archive against the expected SHA-256 before extraction. A checksum failure deletes the partial archive and never installs or launches its contents. A complete cached archive is verified before requesting more bytes. Limits bound downloads to 2 GiB and unpacked content to 4 GiB and 100,000 entries. Extraction rejects traversal, links and special files and removes unsafe permission bits. An OS file lock serializes installs and removals and releases itself after a crash. The installer creates the pack root, staging directories and metadata files with private permissions even with a group-sharing umask. Discovery rejects insecure installed paths; installation rejects insecure roots, lock files and cached archives. Removal validates the root and its ancestors before opening the lock, then checks the existing lock file and all removal candidates before deleting anything. Symlinked roots, lock files and deletion candidates are rejected. These checks do not protect against another process already running as that same user.

Offline or interrupted downloads produce an error with a Retry action and keep the partial file. Retry is another explicit user action. A new pinned version installs beside the old one and atomically changes `current`; older versions remain until removal so existing conversion processes can finish. Reinstalling the same digest replaces that tree, so wait for active document jobs before reinstalling. Updates are explicit installs, never automatic background downloads. Before removal the app must wait for active document jobs to finish. `convt pack remove documents` removes all installed versions and partial downloads, leaving system LibreOffice untouched. Under the same lock, removal also cleans owned, safe `.install-*` and `.previous-*` directories left by a killed installation. It checks their entire trees without following symlinks; an unsafe orphan makes removal fail before deleting the pointer or any pack contents. Unrelated entries are preserved.

For local validation, build with the archive's SHA-256 in `CONVT_DOCUMENT_PACK_SHA256`, then use `convt pack install documents --source file:///absolute/path/documents.tar.gz --sha256 <compiled-digest>`. Both CLI arguments are required together. The supplied digest must match the compile-time pin; runtime arguments cannot authorize another archive. Private unit-test helpers accept explicit pins for synthetic archives. The app must use the embedded release source and must never accept a URL or digest from a document file.

## Size and redistribution

The measured Linux proof pack is about 150 MiB compressed and 407 MiB installed. These include more GUI and language resources than a future headless pack needs. Allow at least 1.2 GiB of free space for the archive, temporary extraction and installed tree; updating can temporarily require an additional installed tree. The Windows verification pack is 445.5 MiB compressed and 1.39 GiB installed, including its app-local runtime. Allow at least 4 GiB of free space for Windows pack installation or replacement. macOS sizes remain unmeasured; budget several hundred MiB of download and up to 1 GiB installed until signed release artifacts are measured. Show the actual pinned archive size in the install dialog rather than these estimates.

LibreOffice is MPL-2.0, with LGPL and other third-party components. Redistribution is permitted subject to those licences. Ship its notices, retain the MPL file-level licence for covered files, and provide the corresponding source for modified covered files, including bootstrap changes. Include the licences and source obligations of every copied native library and bundled font. Keep the pack separate from convt's AGPL code. The local proof records installed LibreOffice versions and available copyright notices; a complete pinned input, source and licence inventory remains a public-release gate.

## App handoff

When a document is selected and LibreOffice is unavailable, show a dialog explaining that document support downloads once and conversions then run offline. Show download size, installed size, destination, Install and Cancel. Cancel before Install makes no network request. Install calls `packs::install_documents()` on a worker thread with the embedded source; `Progress` reports downloaded bytes and total when known, verification, extraction and completion. Show Retry for download errors and a distinct integrity error for checksum failures. After Done, refresh the registry and return to the original conversion with its selected file and options. Conversion itself still requires its usual user action.

Settings needs pack status, explicit update and removal actions. `packs::documents_status()` returns the installed launcher or an error explaining rejection; `packs::installed_documents()` keeps the optional-path discovery interface. The current implementation has byte progress and resumable retry, but no mid-download cancellation API. Closing progress can leave the worker running to completion; the UI must say that, or add cancellation before promising a Stop button. The app code and dialog are owned by the separate app task and are not implemented here.
