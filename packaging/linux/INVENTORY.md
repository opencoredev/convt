# Linux binary inventory

The x86_64 baseline is glibc 2.28. Both Rust binaries and the native codec closure build inside a digest-pinned manylinux_2_28 / AlmaLinux 8 image. After the payload is complete, elf-audit.py checks every ELF file in it, including ffmpeg and ffprobe, and fails the build if any needs a GLIBC version above 2.28 or a library from outside the payload other than the host glibc ABI. Linux desktop integration and display drivers remain host services. The bundle contains no LibreOffice. Document support is a separate opt-in pack.

## Native package layout and host dependencies

The deb and rpm packages reuse the audited payload under `/opt/convt`. `/usr/bin/convt` and `/usr/bin/convt-app` are symlinks to its launchers. The launcher resolves its own symlink, clears inherited `LD_LIBRARY_PATH` before invoking absolute helpers and runs the matching `.bin`. The executables carry a fixed `$ORIGIN/lib` DT_RPATH, so the private closure stays available without leaking loader paths to system LibreOffice children; discovery does not search arbitrary ancestors. Neither package depends on distro FFmpeg, ffprobe, PDFium, libheif or its codec plugins.

Debian and Ubuntu dependencies are `libc6 (>= 2.28)`, `libvulkan1`, `libegl1`, `libwayland-client0`, `libwayland-egl1`, `libfontconfig1`, `fontconfig`, `xkb-data`, `libx11-6`, `libxcursor1`, `libxrandr2`, `libxi6` and `libxrender1`. `python3-nautilus` is recommended. LibreOffice is suggested, so document support remains opt-in.

The RPM requires `/bin/sh`, `coreutils`, `glibc >= 2.28`, `fontconfig`, `xkeyboard-config` and 64-bit SONAME capabilities for `libvulkan.so.1`, `libEGL.so.1`, `libwayland-client.so.0`, `libwayland-egl.so.1`, `libfontconfig.so.1`, `libX11.so.6`, `libXcursor.so.1`, `libXrandr.so.2`, `libXi.so.6` and `libXrender.so.1`. Fedora and RHEL resolve these to `vulkan-loader`, `libglvnd-egl`, `wayland-libs`, `fontconfig`, `libX11`, `libXcursor`, `libXrandr`, `libXi` and `libXrender`. openSUSE can resolve its corresponding library packages by the same capabilities, without Fedora package names in hard dependencies. `nautilus-python` is recommended. LibreOffice is suggested. A functioning display, fonts and a usable graphics driver remain host requirements. Ldd verifies library resolution only.

Desktop metadata claims only `x-scheme-handler/convt`. Package installation never sets MIME defaults. Nautilus uses `/usr/share/nautilus-python/extensions/convt_nautilus.py`; Nemo uses `/usr/share/nemo/actions/convt-zz-more-options.nemo_action`; Dolphin uses `/usr/share/kio/servicemenus/convt-0.desktop`. The static menus open Quick convert, whose choices come from live engine discovery. Package install messages ask users who previously installed menus to run `python3 /usr/share/convt/integrations/install.py --uninstall` as their normal user, then restart the file manager. Cleanup removes marker-owned entries and byte-matching legacy generator output, including old checkout paths. It preserves unrelated files, symlinks and Thunar actions. This explicit user-context step avoids inspecting home directories from a package hook. Nautilus offers More options for every recognized input, even without document targets, and refreshes its caches every 30 seconds. Static menus retain those inputs too. Thunar custom actions are per-user only: its installer stays in `/usr/share/convt/integrations/install.py`, with no package hook writing `uca.xml`.

Build containers and test bases are pinned in `package-images.lock.json`. Packaging-tool dependencies are hash-locked in `package-tools-deb.lock.json` (21 packages) and `package-tools-rpm.lock.json` (69 packages); builder preparation and packaging run with networking disabled. `dpkg-deb` and `rpmbuild` run inside those containers. File order, ownership, timestamps, compression and RPM build host are fixed. Tool versions accompany the artifacts. The Debian postinst and RPM post-install script only print the migration command and document-support guidance. They never inspect or modify home directories. Packages have no signing step. P11 can sign copies of the completed packages with `debsigs` or `rpmsign` in release CI; signing must not alter the unsigned reproducibility inputs. The existing source and licence publication gates apply equally to these native installers.

## Package license metadata

`python3 packaging/linux/license-metadata.py <payload-copy> <metadata-directory>` collects the pinned native notices and produces a DEP-5 `copyright`, `components.spdx.json`, `component-summary.txt`, `rpm-license.txt`, `ffmpeg-static-components.json` and `rust-license-components.json`. The native installers run it against their staging copy, without rebuilding binaries. The RPM License field uses the generated aggregate SPDX expression. Full component notices remain under `/opt/convt/licenses`; the DEP-5 file identifies the installed notice paths and standard Debian license text paths.

The aggregate records reviewed notice terms, manifest-declared Rust licenses and explicit unresolved LicenseRefs. SPDX package license conclusions remain NOASSERTION because a complete per-file binary linkage audit has not been established. This is a verification inventory, not a complete redistribution audit. Notice copyright statements can include license document authors; they are not a substitute for inspecting source-header holders. The codec summaries conservatively include terms for embedded sources recorded in their source-package notices. Those notices also contain source-only tools and packaging files, so their full text is retained for the per-file audit.

`native-notices.lock.json` records the upstream archive URL and SHA-256, exact member path, extracted notice hash and allowed baseline RPM versions. The actual notices are stored in `license-notices/`. The XKB binding also retains Open Text Corporation’s notice from pinned xcb-proto 1.13 `src/xkb.xml`; libxcb requires at least this protocol-source version, while the baseline RPM’s exact generator version is not recorded. Collection fails for an unmapped RPM, absent shipped native library or missing/corrupt pinned notice, including when reusing an earlier origin receipt. Source-copy hashes and post-processing payload hashes are recorded separately. Metadata generation rejects missing or changed locked payload notices, an unmapped shipped ELF and changed FFmpeg configure dependencies.

`rust-license-map.py` runs Cargo metadata offline and locked, filtered to x86_64 Linux. It traverses normal dependency edges from `convt-cli` and `convt-app`, excludes dev/build-only edges and copies cached notice text with hashes into `rust-license-components.lock.json`. It records the source Cargo.lock hash. The source builder must record that same hash in `licenses/cargo-lock.sha256` while building the payload. Metadata generation fails if this receipt is absent or differs from either the Rust map or the current source lock. Never create a retrospective receipt for an existing payload without independent build provenance. Workspace feature unification and proc macros can overinclude components; this conservative graph is not a linker map. Regenerate this lock from the exact release build checkout after dependency changes. Crates with no separate notice file are named individually, with their manifest licenses and unresolved LicenseRefs. They are not silently marked covered.

FFmpeg 7.0.2 is now built from `ffmpeg-source-inputs.lock.json` by `build-ffmpeg.sh`, with external autodetection disabled. Explicit pinned libraries supply AVC, HEVC, VP9, Opus, MP3 and Vorbis; libaom and x265 reuse the audited shared codec closure. Each source and notice is retained. The former static vendor archive is no longer shipped. PDFium's exact revision and DEPS source closure is recorded in `packaging/release/pdfium-source.lock.json`; compiler-runtime notices omitted by the upstream collector are installed separately and hash checked.

`packaging/release/native-sources.lock.json` maps native payload hashes to matching source RPMs and conda GCC source recipes and patches. `appimage-source-closure.lock.json` records the runtime rebuilt from exact sources and static inputs. Source collection excludes general build-tool binaries while retaining their prerequisite pins. The source archive gate checks every retained source, recipe and notice and the runtime actually embedded in the AppImage.

The Linux Rust notice gaps are closed with exact upstream notices, copyright headers and hash-pinned declared SPDX terms where a crate ships no separate licence text. Missing holders stay explicit. Source archives carry the full Linux compilation closure and an archive-only metadata derivation receipt, including original pins and unchanged unit graph. Mac SDK redistribution caveats remain separate blockers and those unrelated sources are excluded from the Linux archive. `CONVT_RELEASE=1 bun run package:linux` and production release dry runs keep the strict notice and source gates.
