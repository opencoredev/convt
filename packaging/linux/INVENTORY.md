# Linux binary inventory

The x86_64 baseline is glibc 2.28. Both Rust binaries and the native codec closure build inside a digest-pinned manylinux_2_28 / AlmaLinux 8 image. After the payload is complete, elf-audit.py checks every ELF file in it, including the static ffmpeg and ffprobe, and fails the build if any needs a GLIBC version above 2.28 or a library from outside the payload other than the host glibc ABI. Linux desktop integration and display drivers remain host services. The bundle contains no LibreOffice. Document support is a separate opt-in pack.

Exact binary and source URLs, versions and SHA-256 digests are in inputs.lock.json. Additional build RPMs are hash-locked in build-rpms.lock.json; the full base image is digest-pinned in build-image.json. Cargo builds offline with Cargo.lock and Rust 1.95.0. The build copies source-package copyright notices and the native runtime RPM licences, PDFium's licence files and FFmpeg's GPL text. FFmpeg's complete configure flags are captured in ffmpeg-configuration.txt. It includes x264, x265, aom, dav1d, vpx, vorbis, opus, mp3lame and other statically linked dependencies listed by those flags. The release inventory must include all of their notices and matching source, not only FFmpeg's own source.

These copyright licences permit redistribution with an AGPL application when their conditions are met. Dynamically loaded LGPL libraries stay replaceable under lib/. Release distribution must provide exact corresponding source, patch and build recipes, and any required relinking material. The current local artifact is a verification build, not a distribution-ready licence/source archive. In particular the downloaded static FFmpeg archive does not contain a complete corresponding-source archive. P11 must obtain and publish that material before public binary distribution. A Rust dependency inventory from Cargo.lock is also still a release gate.

HEVC, H.264 and AAC patent obligations are separate from copyright permission and need platform and jurisdiction review under P12. No legal clearance is claimed here.

The payload also ships the small X11 linkage closure (libxcb, libxcb-xkb, libxkbcommon, libxkbcommon-x11 and libXau), collected inside the pinned AlmaLinux build environment. Their notices are in licenses/rpm. They use permissive MIT/BSD licences. The build rejects every ELF dependency outside the bundle except the host glibc ABI and loader. Linux display servers, XKB data, GPU drivers, the Vulkan loader and driver ICD, Wayland libraries, fontconfig and its font stack remain desktop requirements. GPUI loads several of those at runtime, so a clean ldd result does not establish that a GUI can render. No GUI launch was performed. GUI ldd and help were checked in Ubuntu 22.04 with typical desktop libraries installed.

For this GPUI build, the graphics backend enumerates Vulkan and OpenGL. Host runtime libraries are `libvulkan.so.1` plus the vendor's Vulkan ICD and device access, or `libEGL.so.1` plus the vendor's OpenGL implementation for fallback. Wayland graphics can load `libwayland-client.so.0` and `libwayland-egl.so.1`. Text discovery loads `libfontconfig.so.1` and its distro dependency closure (normally FreeType, Expat, PNG, zlib and Brotli). The desktop must provide an X11 display or Wayland compositor, XKB keyboard data and fontconfig configuration/fonts. The bundle's explicit X11 SONAMEs are libxcb.so.1, libxcb-xkb.so.1, libxkbcommon.so.0, libxkbcommon-x11.so.0, libXau.so.6; these do not require host packages for ELF resolution. The remaining direct host dependencies are libc.so.6, libm.so.6, libdl.so.2, libpthread.so.0 and ld-linux-x86-64.so.2. Codec code can also use the host glibc libmvec.so.1, with glibc 2.28 as the supported build baseline.

The AppImage wrapper uses type2-runtime commit 8f39b89e2ac31e1640b3d3f7e9a5108e6ce805fa. The tool, runtime and licence are pinned in appimage-inputs.lock.json. Its MIT notice and third-party notices are copied into the AppImage. Passing --runtime-file prevents appimagetool from silently downloading an unpinned runtime.

The source recipe applies the pinned Ubuntu security patches. It switches x265 CMake policies CMP0025 and CMP0054 to NEW for CMake 4, disables optional aom libyuv/WebM dependencies, and builds HEIF x265, libde265 and aom encoder/decoder plugins. Native origin receipts record source paths and hashes; the bundle build rejects non-glibc dependencies outside the payload. x265 is built with ENABLE_LIBNUMA=OFF. Its thread pool stays on, but it never calls set_mempolicy, so restricted sandboxes print no libnuma warnings and libnuma is not bundled.

The GCC 15 runtime is pinned by SHA-256 and extracted inside the older builder. Its glibc 2.17 target keeps the 2.28 ceiling, while newer GLIBCXX and GCC symbols prevent the private library path from breaking current host graphics drivers and helper tools. The final ELF audit enforces its glibc requirement too. Its licences are under licenses/compiler.

The local `libheif-explicit-init.patch` adds an exported initializer that registers built-in codecs and increments libheif's initialization count without loading any plugin directory. Convt calls it before capability probing, then loads only its executable-relative absolute bundle directories and an absolute `CONVT_LIBHEIF_PLUGIN_DIR`. Inherited `LIBHEIF_PLUGIN_PATH` and compiled plugin defaults are never consulted by this path. An unpatched system libheif is unavailable to convt because its initializer cannot provide this guarantee. The patch is copied into the payload notices and belongs in the corresponding source release.
